A good AI calling pilot plan answers one question: should we scale this, change it, or stop? Thirty days is enough to find out if you set the goal, the thresholds and the review routine before you start. The plan below gives you a week-by-week structure, success metrics and a decision template.

It works for outbound lead follow-up, inbound answering or appointment reminders. Pick one use case, not three.

## Before day 1: define the pilot

Fill this in and share it with everyone involved.

| Item | Your answer |
| --- | --- |
| Use case | For example, first call to new web leads |
| Owner | One named person |
| Baseline | Current response time, contact rate, booked rate, cost per booked meeting |
| Scope | Lead source, region, hours |
| Volume target | Number of leads or calls |
| Success thresholds | See below |
| Stop conditions | See below |
| Decision date | Day 30 |

If you do not know your baseline, use the previous 30 days of data or run a short measurement first. Use the [call center KPI glossary](/resources/call-center-kpi-glossary) to define each metric once.

## Success metrics and thresholds

Choose five to seven. Example set:

| Metric | Baseline | Pilot threshold |
| --- | --- | --- |
| Median speed to lead | [current] | Set a target you can hit daily |
| Contact rate | [current] | At least equal to baseline |
| Booked rate | [current] | At least equal to baseline |
| Cost per booked meeting | [current] | At or below baseline. See the [cost per booked meeting calculator](/resources/cost-per-booked-meeting-calculator) |
| Show rate | [current] | At least equal to baseline |
| Quality score | n/a | Agreed minimum on the [call quality scorecard](/resources/call-quality-scorecard) |
| Complaints or opt-outs | [current] | No increase |

Thresholds are yours to set. The point is to agree them before seeing results.

## Stop conditions

Agree these upfront so nobody argues later:

- A compliance issue found in review.
- Repeated factual errors that tuning does not fix.
- Opt-outs or complaints rising above your agreed level.
- Leads reporting the experience as poor in multiple transcripts.

If a stop condition triggers, pause the campaign and fix the cause before continuing.

## Week 1: build and test

- [ ] Choose the use case, owner and baseline.
- [ ] Write the agent prompt and knowledge base. See the [prompt template](/resources/ai-voice-agent-prompt-template) and [knowledge base template](/resources/ai-voice-agent-knowledge-base-template).
- [ ] Connect your phone number and calendar.
- [ ] Prepare the list with the [lead list preparation checklist](/resources/lead-list-preparation-checklist).
- [ ] Make at least ten test calls to your own phone, covering objections, silence, interruptions and "are you a robot?".
- [ ] Complete the [launch checklist](/resources/ai-voice-agent-launch-checklist).

Exit criterion: the owner and one other person agree the agent is safe to run on a small batch.

## Week 2: limited launch

- [ ] Launch to a small batch, around a fifth of the planned volume.
- [ ] Review every transcript for the first two days, then a sample.
- [ ] Score reviewed calls on the scorecard.
- [ ] Log fixes: prompt wording, missing facts, handover problems.
- [ ] Apply fixes once a day, not after every call.

Exit criterion: no critical errors in the last ten reviewed calls.

## Week 3: full pilot volume

- [ ] Raise to full pilot volume.
- [ ] Run the human comparison group if you have one: same lead type, handled the usual way.
- [ ] Review a daily sample of ten calls.
- [ ] Track the metric table each Friday.
- [ ] Check handovers: do closers receive summaries and call back promptly?

Exit criterion: metrics stable for several days, not still moving because of changes.

## Week 4: measure and decide

- [ ] Freeze prompt changes for the last week so results are clean.
- [ ] Pull final numbers.
- [ ] Review a larger sample of transcripts, including the worst calls.
- [ ] Collect feedback from the team who took transfers.
- [ ] Fill in the decision template.

## Go or no-go template

| Question | Evidence | Pass? |
| --- | --- | --- |
| Did we meet the metric thresholds? | Metric table | |
| Was quality above the agreed minimum? | Scorecard average | |
| Were there any compliance issues? | Review log | |
| Did handovers work? | Team feedback | |
| Is the cost acceptable at scale? | Cost per meeting | |
| What would we change before scaling? | Fix list | |

Outcomes:
- **Go:** scale in steps, for example double volume, then add a second lead source.
- **Adjust:** extend two to four weeks with named changes.
- **No-go:** stop, record what you learned, and revisit when conditions change.

## Common pilot mistakes

1. No baseline, so results cannot be compared.
2. Changing the prompt daily and not knowing what caused a change.
3. Judging on too few calls.
4. Skipping transcript review.
5. Starting with several use cases at once.
6. Forgetting the human side: closers who are not ready for transfers.

## Reading results fairly

A pilot rarely fits a perfect story. If booked rate matches your baseline but cost per meeting falls and coverage extends to evenings, that may be a win. If booked rate is lower but quality is high, check the list and the prompt first. Read transcripts alongside the numbers, and see [improving an AI agent with call transcripts](/blog/improve-ai-agent-with-call-transcripts).
